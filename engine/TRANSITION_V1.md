# Engine Protocol v2 — Transition v1

Transition handles identify real libobs transition sources owned by the engine.
Kinds are dynamic: the engine enumerates `obs_enum_transition_types` from the
currently loaded modules and does not advertise stale source metadata.

## Methods

```text
transition.kindList
transition.kindDefaults
transition.kindProperties
transition.list
transition.get
transition.create
transition.remove
transition.rename
transition.getSettings
transition.patchSettings
transition.replaceSettings
transition.getProperties
transition.getDuration
transition.setDuration
transition.getState
```

`transition.create` requires a registered kind and accepts optional `name` and
settings. The created source must actually report
`OBS_SOURCE_TYPE_TRANSITION`; a normal input source is never accepted under a
transition handle. Every handle is a canonical positive decimal string and is
invalid after removal or process restart.

Runtime summaries expose the libobs kind/name, engine-owned duration, idle or
running state, progress snapshot, and safe source-A/source-B scene/source
identities when those objects are registered. Raw transition/source pointers
never cross the protocol.

## Settings and duration

Transition kind and instance properties use the existing generic Properties
bridge with target types `transitionKind` and `transition`. Settings reads use
libobs's current settings. Patch and replace validate the object shape, apply
through `obs_source_update`/`obs_source_reset_settings`, read back the current
settings, and emit `transition.settingsChanged` only when the serialized state
actually changed. Equal updates are successful no-ops.

libobs accepts duration as an argument to `obs_transition_start` but does not
expose a persistent transition-object duration property. Therefore
`durationMs` is one engine-owned configuration value in `TransitionEntry` and
is the value Studio passes when starting that object. It is bounded to
`0..600000` milliseconds and emits `transition.durationChanged` on change.

## State and events

The canonical state values are `idle` and `running`. Progress is a read-time
snapshot/telemetry value and does not consume a revision per video frame.
`transition.started` generated by Studio is command-owned and shares the
Studio mutation revision. Libobs's later stop/video-stop signals are queued in
a bounded observer and published as `transition.ended` with an independent
revision before a later protocol request. Overflow requires the normal
`session.resyncRequired` path.

Canonical events are:

```text
transition.created
transition.removed
transition.renamed
transition.settingsChanged
transition.durationChanged
transition.started
transition.ended
```

`transition.trigger` is intentionally not implemented; Studio owns the
explicit Preview-to-Program transition contract.

Removing a Transition selected by Studio returns `object_in_use`. Removing a
running unselected Transition returns `busy`; removal disconnects its signal
observers before releasing the libobs source.
